# Первый настоящий PSP-образ: Magna Carta (ULJS00042)

Образ `Magna_Carta_Portable_JPN_PSP-DMU.iso`, 1 611 497 472 байт,
md5 `91f4baca1f78eaf01e88d92a0437bc07`. Разобран 2026-10-04.

## Что внутри

Обычный ISO 9660, 786 864 сектора по 2048 байт.

```
system id: "PSP GAME"
volume id: ""            (пусто — не ошибка, у этого образа он пустой)
path table: 82 байт
```

Структура:

```
/UMD_DATA.BIN                  48 байт
/PSP_GAME/PARAM.SFO           472 байт
/PSP_GAME/ICON0.PNG
/PSP_GAME/SYSDIR/EBOOT.BIN    5 613 888 байт   LBA 32    <- игровой модуль
/PSP_GAME/SYSDIR/UPDATE/      EBOOT.BIN 3 951 712, DATA.BIN 14 809 632
/PSP_GAME/USRDIR/             данные игры (MUSIC.PPS 625 МБ, SHIP.PPS 309 МБ, MOVIE/*.PMF)
/PSP_GAME/USRDIR/UPDATE/      PARAM.SFO
```

`PARAM.SFO`:

| ключ | значение |
|---|---|
| DISC_ID | `ULJS00042` |
| REGION | `UG` (Япония, UMD) |
| DISC_VERSION | 1.03 |
| PSP_SYSTEM_VER | 2.60 |
| TITLE | マグナカルタ |

Это порт PS2-игры на PSP, поэтому в `UPDATE/` лежат данные оригинала.

`UMD_DATA.BIN` — физический идентификатор карты:
`ULJS-00042|D86CC62E0E2E8C1E|0001|G`

## Главное: EBOOT.BIN зашифрован

```
сигнатура:  7e 50 53 50   = "~PSP"
модуль:     softmax        (игровой)
            updater        (обновляющий, из UPDATE/)
```

Это формат розничного UMD, а не исполняемый ELF. Расшифровка зависит от
`DISC_ID` и версии прошивки, то есть от данных, которые мы теперь знаем.

Разобрать таблицу импортов и NID без расшифровки нельзя. Это текущий блокер.

## Проверено попутно

### Фикс ISO 9660 подтверждён на настоящем образе

Ошибка в `path_table_size` (поле занимает 8 байт, а не 4) найдена на
синтетическом ISO. На этом образе она тоже видна: `path_table_size` = 82,
старшая половина-зеркало тоже 82, а `root_dir_record` начинается с байта
`0x22` по смещению 156. Утилита разбирает этот образ без ошибок.

### Ошибка в утилите: EBOOT.BIN не в USRDIR

Первая версия искала `EBOOT.BIN` только в `USRDIR`. На синтетическом ISO
это работало, на настоящем — нет: у розничных игр модуль лежит в
`PSP_GAME/SYSDIR`, а `USRDIR` содержит только данные игры.

Исправлено: поиск идёт по `SYSDIR`, затем `USRDIR`. `USRDIR` — это каталог
для homebrew и демо, а не для розничных игр.

После исправления извлечение побайтовое: md5 совпал с прямым чтением
по LBA (`2da0f14c35bb02f10ceb5954e424aa4e`).

### Ошибка в обходе дерева: рекурсия на записи "."

Первый вариант обхода падал с `RecursionError`. Причина: запись `.` в ISO
9660 — это однобайтовое имя `0x00`, и код обрезал его до **пустой строки**,
а пустая строка не совпадала с фильтром `(".", "..")`. Обход уходил вглубь.

Исправлено: `.` и `..` распознаются по длине имени и значению байта **до**
обрезки. Проверено: обход даёт 5 каталогов и 76 файлов без зацикливания.

## Заголовок ~PSP — что подтверждено

Сигнатура, версия и имя модуля читаются однозначно:

```
+0x00  "~PSP"              4 байта
+0x04  версия              байт
+0x0A  имя модуля          28 байт, "softmax" с нулями
```

Смещение имени 0x0A, а не 0x0C — проверено на обоих файлах образа. То есть
между версией и именем есть ещё два байта (`01 01` в этом файле), и это
не хвост заголовка `modname`.

Остальные поля заголовка не разобраны: по смещениям 42..61 лежат значения
`0x0055A7E8`, `0x0055A940`, `0x002B8EAC`, `0x002CF488`, `0x00119E60`, которые
не похожи ни на адреса PSP (обычно `0x088xxxxx`), ни на размеры. Без
расшифровки их смысл установить нельзя.

## Что нужно дальше

Расшифрованный EBOOT.BIN. Два пути:

1. **Готовая выгрузка** из работающей PSP или из инструмента дешифрования.
   Самая быстрая проверка: первые 4 байта должны стать `7f 45 4c 46`.
2. **Своя реализация дешифрования** по алгоритму `~PSP` (`DISC_ID` = ULJS00042).
   Алгоритм детерминирован и проверяем сам собой: если результат начинается
   с `7f 45 4c 46`, ключ верен.

Пока нет того и другого, таблицу импортов не прочитать.
