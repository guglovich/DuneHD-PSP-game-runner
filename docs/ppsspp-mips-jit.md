# JIT MIPS→MIPS в PPSSPP: проверка утверждения из интернета

Утверждение: «в начале проекта PPSSPP было MIPS > MIPS».
**Верно по факту, но это пустой каркас без единой реализованной инструкции.**

Проверено по репозиторию <https://github.com/hrydgard/ppsspp>, а не по вторичным
источникам.

## Что внутри

**Каркас есть, реализации нет.** Все функции компиляции инструкций — пустые:

```cpp
void Comp_IType(MIPSOpcode op) {}
void Comp_RType3(MIPSOpcode op) {}
void Comp_Jump(MIPSOpcode op) {}
void Comp_Syscall(MIPSOpcode op) {}
// ... и ещё ~70 таких же, включая весь VFPU
```

Реализовано только:
- `Jit::Compile` / `DoJit` — цикл по блоку, чтение опкода, вызов `MIPSCompileOp`;
- `CompileDelaySlot` — обработка слота задержки;
- `EatInstruction` — подсчёт инструкций и циклов;
- `WriteExit` / `WriteExitDestInR` / `WriteSyscallExit` — выходы из блока с
  связыванием блоков (`enableBlocklink`);
- `FlushIcache` — сброс кэша команд после записи кода;
- `AddContinuedBlock` / `ProxyBlock` — продолжение блока.

`Comp_Generic` — единственный непустой, и он **вызывает интерпретатор**:
`QuickCallFunction(V1, MIPSGetInterpretFunc(op))`. То есть блок
компилируется, а каждая инструкция исполняется через интерпретатор.

## Вывод для нашего проекта

**Переносить нечего.** Это не «готовый JIT, который мы не нашли», а заготовка,
которую авторы сами удалили как незавершённую.

Важнее другое: **JIT нам не нужен в принципе.** PPSSPP пишет JIT, потому что
работает на x86/ARM и обязан переводить MIPS-код гостя в свою ISA. Мы
работаем на MIPS (Sigma SMP8642) и исполняем гостя **нативно** — это ровно та
архитектура, ради которой в PPSSPP заводили MIPS-бэкенд, но нам не нужна ни
трансляция, ни интерпретатор.

Единственное, что из каркаса теоретически полезно — идеи по организации кэша
блоков и связыванию выходов. Но у нас нет блоков: гость исполняется сам.

## GCW Zero

GCW Zero — портатив на Ingenic JZ4770 (MIPS32r2, XBurst), 320×240, 512 МБ.
Это та платформа, ради которой MIPS-бэкенд и заводили.

Практический вывод: на GCW Zero PPSSPP не мог использовать этот JIT (он пуст),
значит там работал интерпретатор. Для нас GCW Zero интересен только как
**эталон ограничений MIPS32r2**: если код работает там, он работает и на
SMP8642. Но прямого кода оттуда не берём.
