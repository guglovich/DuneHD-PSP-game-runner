# Выход кадра из плагина: измеренные адреса и сигнатуры

Канон по **адресам и соглашениям вызова** GFX-пути. Порядок вызовов и причина
ошибок — в `Dune Max/docs/hle-injection.md`, дублировать их здесь нельзя.

Дата снятия адресов: 2026-10-09, источник — `.dynsym` бинарника `shell`
(`Dune Max/tmp/shell_live`). Адреса **перепроверены независимо** от
документации и совпали.

## Главное: `dlsym` не нужен

`shell` **не PIE**, значения символов у него абсолютны, а нужные функции
экспортированы в `.dynsym`. Значит их можно звать по абсолютному адресу.

Это отличает наш плагин от `test_frame` из соседнего проекта: тот обязан был
доставать адреса через `dlsym(RTLD_DEFAULT, …)`, а наш собран `-nostdlib` без
единой неразрешённой ссылки и **не может** вызвать `dlsym` вообще. Здесь
это не помеха, а преимущество: зависимости и связывание не нужны.

доказывающих».

## Сигнатуры — по дизасму, не по памяти

| Функция | Что делает | Код команды |
|---|---|---|
| `MY_GFX_DisplayPicture(a0,a1,a2,a3)` | `SEND_GFX_COMMAND(cmd, &args, 16)`, 4 слова в стек | `0x10E0` |
| `MY_GFX_WaitForPicture(a0)` | кладёт **только `a0`**, размер 4 | `0x10E1` |
| `MY_GFX_Surface(a0,a1,a2)` | 3 аргумента; **кэшируется** по паре `(a0,a1)` в таблице с шагом 8 | `0x10CB` |
| `MY_GFX_FillRectangle(a0..a3, +3 стековых)` | полезная нагрузка 20 байт (5 слов) | `0x10CD` |

Три предостережения, все из дизасма:

1. **`MY_GFX_Surface` кэшируется в userspace.** Повтор с той же парой
   `(a0,a1)` не отправляет команду вовсе. Значит вызов без смены состояния
   молча ничего не делает — и это не «отправка кадра».
2. **`MY_GFX_WaitForPicture` игнорирует `a1..a3`.** В `args` кладётся ровно
   одно слово при `size = 4`.
3. **`MY_GFX_FillRectangle` требует ненулевого 5-го аргумента.** Проверка
   `beqz` на стековом слоке идёт **до**Anything, и при нуле функция выходит
   сразу, не отправив команду. Итого у неё **7 аргументов**, а не 4.

Полезная нагрузка `FillRectangle` — `[a2, a3, стек1, стек2, стек3]`; `a0` и
`a1` уходят в отдельную команду `SEND_GFX_COMMAND(3, a0, a1)`, если ненулевой
второй стековый аргумент. То есть у неё побочный вызов, о котором легко не
знать.

## Чего в репозитории нет

`Dune Max/tmp/test_frame_plugin.zip` содержит **раннюю, неудачную** версию:
в `NEEDED` — `libdirectfb.so`, `libdirect.so`, `libfusion.so`, `libc.so`, а по
символам только `DirectFBInit` и `DirectFBCreate`. Ни `RUA*`, ни `gbus_*`, ни
`MY_GFX_*`, ни строк-маркеров шагов там нет.

То есть рабочего кода GFX/RUA-пути **в репозитории не сохранилось** —
есть только описание в `hle-injection.md`. Писать придётся заново, и опорой
будут адреса и сигнатуры выше плюс порядок вызовов из документации.

## Правило вызова

Функции `shell` — обычные MIPS-функции, и PIC-ABI требует `$t9` = адрес
функции. Наш плагин собран PIC, поэтому вызов через объявленный указатель
компилятор сам построит как `lui $t9 / addiu $t9 / jalr $t9` — условие ABI
выполнится без ручной подстановки.

## Игра для теста — только 2D (2026-10-09)

Игра, которая сейчас стоит в тесте — **Magna Carta PSP**, и это
**полноценная 3D**. Мы всё это время гоняли 3D-игру, хотя аппаратное
ускорение PSP (GE) мы не эмулируем вовсе. Значит весь прогон шёл по пути,
который нам закрыт по построению, и результат «5 вызовов и сбой» ничего не
говорит о 2D.

Отсюда порядок работы:

1. **pspsdk** (`github.com/pspdev/pspsdk`) — для тестирования и отладки
   2D-вызовов: там есть заголовки и примеры вызовов `sceGu*`/`sceGum*`.
2. **jpcsp** (`github.com/jpcsp/jpcsp`) — старый простой эмулятор с парсингом
   GE; оттуда берём разбор списков команд GE.
3. **Сменить игру на 2D** — нужна игра, которая рисует через 2D, а не через
   GE, иначе тест снова упрётся в неэмулируемое железо.

Прежняя игра остаётся в истории как «3D, не наш путь», а не как эталон.
