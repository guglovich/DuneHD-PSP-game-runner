# Плеер Dune HD Max — что установлено при разведке

Все данные проверены на живом плеере 2026-10-04. Метод и каналы — в
`README.md` соседнего проекта (`Dune Max`), здесь только выводы для
портирования игр.

## Подтверждено рабочим

| Что | Как проверено | Результат |
|---|---|---|
| Кросс-сборка под MIPS32 LE | `make` | 3 бинарника, все `ELF 32-bit LSB MIPS32 rel2` |
| Запуск своего кода на плеере | `ld-musl-mipsel.so.1 ./psp-hle` | работает, падение в HLE-обработку видно |
| Извлечение EBOOT.BIN из ISO | `iso_extract_eboot` | файл извлечён, md5 совпал с оригиналом |
| Загрузка ELF на MIPS-целевой | `psp-hle EBOOT.BIN` | процесс стартует, PT_LOAD виден после исправления теста |

## Каналы доставки файлов на плеер

| Канал | Состояние | Примечание |
|---|---|---|
| SMB (`smbclient put`) | работает | **основной канал**; SMB1/NТ1, шара `DuneHDD_*` = `/D` |
| `ssh ... "cat > файл" < локальный` | работает | для файлов с пробелами в пути — `smbclient -c` их ломает |
| NFS (`unfsd` на плеере) | сервер поднят | `unfsd` PID есть, порт 2049 открыт; **клиента на хосте нет**, поэтому как канал доставки не используется |
| FTP | только чтение | для выгрузки с плеера |
| `scp` | **не работает** | на плеере нет sftp-сервера |

Пробел в пути локального файла ломает `smbclient -c 'put ...'` — команда
разбирается по `;`, и путь с пробелом схлопывается. Для таких файлов
используется вариант с `ssh cat`.

## Ввод: это главное ограничение

**ИК-управление монопольно занято процессом `shell`.** Это установлено, а не
предположено:

```
/dev/ir          major 253   ->  держит PID 1207 = `shell first_run`
/dev/input/event0..3         ->  open() даёт "No such device"
/dev/uinput                  ->  отсутствует
```

* `open("/dev/input/eventN")` → `No such device`: узлы созданы, но за ними
  нет драйвера, потому что IR обслуживает `irkernel`, а не evdev.
* `open("/dev/ir")` из постороннего процесса → `Input/output error`:
  устройство уже открыто `shell`.
* `/dev/input/mice` открывается, но при чтении не выдаёт данных.

Модули `irkernel` и `fipkernel` загружены, `/proc/bus/input/devices` пуст.

**Следствие для HLE:** получать кнопки из своего процесса нельзя. Это
то же ограничение, что описано в `Dune Max/AGENTS.md` для `/dev/mum0` и
`/dev/em8xxx0` — открывать устройства, которыми владеет `shell`, из
постороннего процесса опасно для плеера.

### Значит ввод надо брать из процесса shell

Рабочие варианты, в порядке предпочтения:

1. **Действие плагина с параметром.** Плагин отдаёт `action_map` с
   параметрами, `shell` передаёт их в обработчик. Нажатия приходят в
   уже работающем контексте `shell` — устройство открывает он.
   Механизм разобран: `PHP → action_map → XML → C++ → gui_action_execute_all`.
2. **`system()`/`popen()` из `shell`** — процесс запускается от `shell`,
   но ввод всё равно принадлежит `shell`, а не потомку.
3. **Хук GUI-слоя** — правка `shell` целиком. Дороже всего.

Вариант 1 — единственный, где не нужно ни патчить прошивку, ни делить
устройство с работающей оболочкой.

## Графика: подтверждённые ограничения

Из `Dune Max/docs/`:

* **3D нет вообще.** Только 2D-композит: заливки, блитчинг, альфа,
  масштабирование, глифы. Примитивов поворота нет.
* **Аппаратный апскейл работает.** 320×240 растягивается на 1920×1080
  силами DSP, CPU не участвует. Это основа схемы «рисовать в маленький
  буфер».
* **Пропускная способность не узкое место.** Полноэкранный проход с
  альфой — 8.3 МБ, при 60 fps 497 МБ/с из пика 1332 МБ/с.
* **Узкое место — CPU на сборку команд.**

Путь вывода кадра: GFX-примитивы → OSD-поверхность → **Video Scaler** →
HDMI. То есть кадр игры может идти через OSD-слой и масштабироваться
железом.

## Формат PSP, который нужен загрузчику

Подтверждено разбором настоящего EBOOT.BIN и тестовым генератором:

* ELF32, little-endian, `EM_MIPS` (8), тип — `ET_EXEC`.
* Адреса пользовательского модуля: база **`0x08804000`**, это
  `kDefaultPspUserLoadBase` из PSPRecomp. Адреса в ELF относительные к
  этой базе, поэтому при загрузке к базе добавляется.
* `.rodata.sceModuleInfo` — 52 байта: `attributes`, `version`, `name[28]`,
  `gp`, `ent_top`, `ent_end`, `stub_top`, `stub_end`.
* Импорты лежат между `stub_top` и `stub_end`, записи по 20 байт, у каждой
  — имя библиотеки, число NID, таблица NID, таблица стабов.

**Модули PRX** (`e_type = 0xFFA0`) — это другой случай: там обязательны
релокации (`R_MIPS_26/32/HI16/LO16`) из секции типа `0x700000A0`.
Обычный `EBOOT.BIN` — `ET_EXEC`, и для него релокации не нужны.

Рекомпиляция кода **не требуется**: PSP (Allegrez) и SMP8642 — оба MIPS32
little-endian. Нужен только перехват системных вызовов.

## Что уже сделано в проекте

* `tools/mk_test_eboot.py` — генератор тестового EBOOT.BIN со структурой
  PSP: PT_LOAD-сегмент, `.rodata.sceModuleInfo`, точка входа, которая пишет
  маркер в `$v0`. Содержит проверку, что таблицы заголовков не наезжают на
  образ: без неё `phoff` совпадал с началом `.text` и загрузчик читал
  инструкции вместо заголовков.
* `tools/iso_extract_eboot.c` — разбор ISO 9660 до `PSP_GAME/USRDIR/EBOOT.BIN`.

### Грабли в ISO 9660 (стоили времени, зафиксированы в коде)

1. **Поле `path_table_size` в PVD занимает 8 байт, а не 4.** Оно
   both-endian, как и остальные such-поля. Ошибка на 4 байта сдвигает
   `root_dir_record` с 156 на 152, и читается мусор — LBA 2228224.
   Проверено на двух независимо собранных ISO.
2. Смещение `root_dir_record` — **156**, а не 152.
3. `logical_block_size` — 128, both-endian, значение 2048.
4. Директория — это цепочка записей переменной длины в пределах сектора;
   запись нулевой длины означает конец сектора, а не конец каталога.

Обе позиции зафиксированы `_Static_assert`, чтобы раскладка снова не
разъехалась молча.

## Что дальше по приоритету

1. **Ввод** — без него игру не запустить. Нужен способ получать кнопки
   не в конкуренции с `shell`.
2. **Запуск гостевого кода.** Для MIPS→MIPS это не рекомпиляция, а
   подготовка окружения: стек, `gp`, разбор импортов через NID, вызов
   точки входа. Перехват `sce*` идёт через NID, а не через номера —
   номера в заголовке мои и настоящие не совпадают.
3. **Видеовыход.** Проверить, можно ли из своего процесса отдать кадр в
   OSD/Video Scaler, не открывая устройства Sigma (риск описан в AGENTS.md).
4. **NID-реестр** — сопоставление NID с именами функций; без него
   резолвить импорты нечем.
